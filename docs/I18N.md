# Internationalisation

The app ships in **English, Tamil, Sinhala and Arabic**, with full right-to-left
layout for Arabic. Every user-visible string comes from a translation file —
there are no hard-coded English strings in any screen.

---

## How it fits together

```
src/i18n/
  index.ts              i18next setup, RTL handling, language persistence
  locales/en.json       514 keys
  locales/ta.json       514 keys — same shape
  locales/si.json       514 keys — same shape
  locales/ar.json       514 keys — same shape
```

Translation files are **bundled with the app**, not fetched at runtime. That
means text is available instantly, works offline, and costs no Firestore reads.

Which languages are *offered* is data, though. `languages/{code}` in Firestore
carries an `enabled` flag an admin can toggle from the dashboard, so a language
can be hidden without a release. `languageService.listLanguages()` falls back to
the bundled list if Firestore is unreachable, so the splash screen always has
something to show.

## Using it in a component

```tsx
import { useTranslation } from 'react-i18next';

const { t } = useTranslation();

<Text>{t('lesson.title')}</Text>
<Text>{t('lesson.week', { number: 3 })}</Text>
<Text>{t('common.showing', { count: 20, total: 143 })}</Text>
```

For the current language and direction:

```tsx
import { useLanguage } from '@/contexts/LanguageContext';

const { language, rtl, available, setLanguage } = useLanguage();
```

`language` is also the right value to pass as a locale to the date and number
helpers in `src/utils/date.ts` and `src/utils/format.ts`, which is why list
screens thread it into their row components.

## Key naming

Keys are grouped by domain, one level deep:

```
app.*          name, tagline, greeting
common.*       save, cancel, delete, loading, noResults …
auth.*         login, register, recovery, field labels
validation.*   field-level error messages
errors.*       Firebase error codes mapped to human sentences
nav.*          navigation labels
dashboard.*    dashboard cards and quick actions
calendar.* video.* article.* lesson.* material.*
attendance.* quiz.* result.* notification.* announcement.*
profile.* admin.* settings.* confirm.* empty.*
permissions.*  one entry per permission flag, for the permission editor
```

Two conventions worth keeping:

- **`errors.*` keys mirror Firebase error codes.** `utils/errors.ts` maps a
  caught error to one of these keys, so a new Firebase failure mode needs a new
  key rather than a new `if` in a screen.
- **`permissions.*` has one key per flag** in `src/types/permissions.ts`. The
  permission editor renders `t('permissions.' + flag)`, so adding a flag without
  adding its key shows the raw flag name — which is a visible reminder, not a
  crash.

## Right-to-left

Arabic is marked `rtl: true` in `src/constants/app.ts`, and `applyLanguage()` in
`src/i18n/index.ts` handles the platform differences:

**Web** sets `dir="rtl"` and `lang` on `<html>`. It takes effect immediately.

**Native** calls `I18nManager.forceRTL()`. React Native only applies a direction
flip fully **after an app reload**, so `applyLanguage()` returns
`{ needsRestart: true }` and `LanguageProvider` shows an alert asking the user to
reopen the app. Force-restarting underneath someone mid-task would be worse than
asking.

Layouts use `flexDirection: 'row'` with `gap`, and logical spacing rather than
hard-coded `left`/`right` offsets, so most of the UI mirrors automatically.

## Adding a fifth language

Three steps, no component changes.

**1. Create the locale file.**

```bash
cp src/i18n/locales/en.json src/i18n/locales/ur.json
```

Translate the values. Leave the keys exactly as they are — the structure must
match `en.json` key for key. To check afterwards:

```bash
node -e "const f=r=>Object.entries(require(r)).flatMap(([k,v])=>typeof v==='object'?Object.keys(v).map(x=>k+'.'+x):[k]);const a=f('./src/i18n/locales/en.json'),b=f('./src/i18n/locales/ur.json');console.log('missing:',a.filter(k=>!b.includes(k)));console.log('extra:',b.filter(k=>!a.includes(k)))"
```

**2. Register it in two places.**

`src/constants/app.ts`:

```ts
export const LANGUAGES = [
  // …
  { code: 'ur', name: 'Urdu', nativeName: 'اردو', rtl: true },
] as const;
```

`src/i18n/index.ts`:

```ts
import ur from './locales/ur.json';

export const resources = {
  // …
  ur: { translation: ur },
} as const;
```

`LanguageCode` in `src/types/models.ts` is derived from `LANGUAGES`, so
TypeScript will point at anything else that needs updating.

**3. Add the Firestore row** so admins can toggle it:

```bash
npm run seed -- --key ./serviceAccount.json
```

or add `languages/ur` by hand in the console, or press **Refresh** on the
admin Languages screen, which re-seeds from the bundled list.

### If the new language is RTL

Set `rtl: true` and nothing else changes — the direction handling above is
generic. Do check the splash screen and the quiz player on a device, since those
are the two screens with the most custom positioning.

## Translation notes

The four bundled translations were written for this app's context rather than
machine-translated field by field. A few choices worth preserving if you revise
them:

- **`app.greeting`** is *As-salāmu ʿalaykum* in each script (`السلام عليكم`,
  `அஸ்ஸலாமு அலைக்கும்`, `අස්සලාමු අලෛකුම්`) rather than a generic "Hello".
- **Islamic terms** keep their conventional local rendering rather than a
  literal translation.
- **Arabic uses `فصل` for a class** in the classroom sense.
- **Error messages are full sentences** in every language, because they are read
  under stress.
- **Interpolated counts** (`{{count}}`, `{{total}}`, `{{number}}`) sit where the
  target language puts them, not where English does.

If you machine-translate a fifth language, get a speaker to review at least
`auth.*`, `validation.*` and `errors.*` — those are the strings a confused user
reads.
